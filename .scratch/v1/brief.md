# Личный трекер затрат: стартовый бриф

Статус: спека v1 проработана, код не начат. Веб первым, мобилка позже.
Язык продукта: русский. Валюта по умолчанию: тенге.

## 1. Назначение и главная задача

Личное веб-приложение для учёта затрат семьи (владелец плюс жена, общие
счета) и расчётов с компанией. Задачи v1:
* Быстро записывать любую денежную операцию, в том числе на лету.
* В любой момент показывать: сколько всего денег, сколько свои и сколько
  компании, кто кому должен (пользователь и компания), из каких операций
  сложился долг.
* Экспорт для анализа в Claude, импорт по той же схеме.

## 2. Расчётная модель долга

Три величины, все выводятся из журнала (баланс не хранится числом):
* Остаток счёта (balance): сколько всего денег на счёте.
* Аванс компании на счёте (card_advance): сколько из них денег компании.
  Всегда >= 0. Компания кидает их под рабочие оплаты (реклама и т.п.).
* Долг (двусторонний): company_owes_me и i_owe_company. Итог = разница.

Ключевой принцип: карта и чьи деньги это разные вещи. На одной карте
лежат и свои, и деньги компании. Поэтому источник не угадывается по карте.

Два тега определяют эффект:
* Назначение (purpose): личное (personal) или работа (work).
* Источник (source): свои (own) или деньги компании (company).

Таблица трат:
| Источник | Назначение | Эффект |
|---|---|---|
| свои | работа | компания должна мне += сумма |
| компании | личное | я должен компании += сумма, аванс -= сумма |
| компании | работа | аванс -= сумма, долг не трогается |
| свои | личное | нейтрально |

Правило аванса: рабочая (или личная деньгами компании) трата сначала
гасит аванс на счёте, остаток суммы идёт дальше (авто-сплит). Аванс в
минус не уходит.

Проваливание в траты: итог с компанией раскрывается на две стороны
(компания должна вам / вы должны компании), каждая разворачивается в
список конкретных операций, из которых сложилась. Плюс отдельный список
взаимозачётов.

Производные для обзора: свои деньги на счёте = остаток минус аванс; всего
своих = сумма по счетам; всего денег = сумма остатков; личные траты за
период = сумма трат personal.

Расчёт с компанией всегда в тенге.

## 3. Все виды операций (entry_type)

1. expense (трата). Теги source и purpose. Источник спрашивается только
   при личном на счёте с авансом, иначе выводится. Авто-сплит при
   превышении аванса.
2. income (поступление своих денег). Зарплата, кешбэк, возврат от
   человека, продажа. Остаток растёт, долг и аванс не трогаются.
3. transfer (перевод между своими счетами). Пять назначений
   (transfer_purpose):
   * repay_debt: погасил свой долг свои деньги на карту, i_owe -= k,
     аванс[куда] += k. Только до нуля.
   * top_up_advance: пополнил аванс переводом (деньги компании).
   * move_company: перекладываю деньги компании между счетами, аванс
     уезжает с одного на другой, итог не меняется.
   * take_advance: взял аванс себе на личное, аванс -= , i_owe += .
   * move_own: перекладываю свои деньги, только перемещение остатка.
   Комиссия: списывается со стороны, чьими деньгами перевод.
4. company_topup (пополнение от компании на счёт). Аванс += сколько легло.
   Три случая по комиссии: компания с запасом (аванс += цель); комиссию
   плачу я (аванс += цель, остаток += сколько легло, компенсация комиссии
   сначала гасит i_owe, остаток в company_owes_me, см. ADR-0003); урезал
   перевод (аванс += сколько дошло).
5. company_advance_return (компания забирает неиспользованный аванс).
   Аванс -= , остаток -= , долг не трогается. Не больше текущего аванса.
6. settlement (взаимозачёт). Два направления: я вернул компании
   (i_owe -= ), компания вернула мне (company_owes_me -= ). Только до нуля.
7. adjustment (корректировка остатка). Три режима: plug вне аналитики
   (подгонка остатка, не в разрезы трат), plug в аналитике (то же, но
   учитывается под общим заголовком), и флаг "это аванс компании" для
   правки аванса. Пакетная крупная запись это НЕ adjustment, а обычная
   трата или поступление одной строкой с заголовком.
8. refund (возврат от мерчанта). Привязан к исходной трате, откатывает её
   эффект пропорционально. Только на тот счёт, с которого платили.

Наличные: ведутся как счёт (type cash). Снятие и возврат нала через
перевод между картой и наличными.

Долг семье или друзьям: отдельным типом операции НЕ моделируется. Жена в
общем котле (одна сторона "свои деньги"), отдельного расчёта с женой нет.
Напоминание "вернуть другу" делается заметкой, не операцией.

## 4. Фичи: must (v1) и later

Must (v1):
* Веб кабинет.
* Google авторизация.
* Справочник счетов (карты, счета, наличные) с добавлением и архивом.
* Справочник категорий.
* Все 8 типов операций и движок расчёта (функции Postgres).
* Способы ввода: полная запись; быстрый capture (черновик, сумма, счёт,
  личное/работа, текст); заметка (текст и/или скрин, не запись); импорт
  файла.
* Инбокс (разбор черновиков и заметок), бейдж.
* Заметки с вложениями (скрин по желанию, можно только текст).
* Импорт и экспорт (CSV, Excel, JSON) по единой схеме (round trip).
* Валюта: операции в валюте с тенговым эквивалентом, курс Нацбанка по
  умолчанию, свой курс, или ввод суммы в тенге.
* Живой предпросмотр эффекта операции на аванс и долг в форме.
* Обзор: итог с компанией (две стороны плюс нетто одной карточкой), всего
  денег (своих плюс компании одной карточкой), личные траты за период,
  остаток и аванс по каждому счёту.
* Баланс с компанией с раскрытием в конкретные операции.
* Claude Code ingestion: запись в ту же базу из разобранных заметок.

Later (после MVP):
* Мобилка Android (Flutter) и виджет быстрого capture.
* Встроенная аналитика и графики (пока анализ в Claude).
* Распознавание чеков через API (сейчас разбор фото вручную через Claude
  Code вне приложения).
* AI code reviewer в CI, расширение тестов.

## 5. Edge cases и спорные кейсы (и к чему пришли)

* Запись задним числом плюс бегущий аванс: считаем по РЕАЛЬНОЙ дате
  операции, не по дате ввода, с хронологическим реплеем. Итог может
  зависеть от реальной даты (своя рабочая трата до пополнения это долг
  компании перед вами, а после пополнения уже списание с аванса).
* Авто-сплит: всегда включён, без галочки. Аванс гасится до нуля, остаток
  суммы идёт из своих денег. В минус аванс не уходит.
* Личная трата деньгами компании больше аванса: так же сплитится.
* Деньги как int в минимальных единицах (тиыны): 1500 тенге = 150000.
  Без float.
* Валюта: аванс и долг всегда тенге. Трата или перевод могут быть в
  валюте. Тенговый эквивалент тремя способами (Нацбанк на дату, свой курс,
  сумма в тенге). Дельта остатка в валюте счёта (для тенговой карты это
  тенговый эквивалент).
* Правка и удаление: после любого изменения запускается recompute
  (реплей аванса счёта по дате), ledger перестраивается.
* Порядок в один день: тайбрейк детерминированный (occurred_on, затем
  occurred_at при наличии, затем created_at, затем seq). Итоги в
  приоритете, точный порядок не критичен, время можно тянуть из выписки.
* Округление при сплите: аванс списывается полностью целыми тиынами,
  остаток (включая дробную часть пересчёта) идёт из своих, дрейфа нет.
* Refund курс: откатываем фактически списанный тенговый эквивалент
  исходной; курсовую разницу выносим отдельной записью adjustment.
* Refund только на тот счёт, с которого платили.
* Межвалютных переводов между своими счетами нет (оба счёта одной валюты).
* Смешанный перевод (часть долг, часть аванс) не делаем: одна запись одно
  назначение, при необходимости два перевода.
* Взаимозачёт и погашение только до нуля, переход через ноль запрещён,
  свои деньги на аванс сверх долга не кидаем.
* Рассрочка: не особый тип, пишется руками как обычная трата в момент
  каждого платежа.
* Неизменность: валюту счёта с операциями менять нельзя; смена типа записи
  при правке это полная пересборка её ledger строк.
* Архив вместо удаления: архивировать счёт с ненулевым остатком или
  авансом нельзя (сначала обнули); удалять счёт с операциями нельзя,
  только архив.
* Дедуп: отпечаток (дата, счёт, сумма, валюта, тип, описание) плюс
  external_id как ключ идемпотентности импорта; возможные дубли в
  предпросмотре, молча не создаём.
* Черновики и заметки на баланс не влияют, пока не разобраны.
* Импорт атомарный: всё или ничего, невалидные строки не идут в draft
  (ADR-0004).

## 6. Модель данных (сущности)

* accounts: id, user_id, name, bank, type (card/bank_account/cash), mask,
  owner (me/spouse), currency, balance, is_archived.
* categories: id, user_id, name, icon, is_archived.
* entries (единая таблица всех операций): id, user_id, type, status
  (draft/done), occurred_on, occurred_at, amount_minor, currency,
  amount_kzt_minor, rate, rate_source, account_id, to_account_id,
  category_id, purpose, source, source_pending, transfer_purpose,
  fee_minor, fee_payer, settlement_direction, adjustment_mode,
  adjustment_sign, adjustment_affects_advance, in_analytics, comment,
  title, parent_entry_id, source_note_id, fingerprint, external_id,
  import_batch_id.
* ledger_entries (журнал, источник правды): id, user_id, entry_id,
  account_id, target (balance/card_advance/company_owes_me/i_owe_company),
  delta_minor, occurred_on, seq.
* notes: id, user_id, text, attachment_path, status (new/processed),
  linked_entry_id.
* attachments: id, user_id, entry_id, file_path, kind.
* fx_rates: rate_date, currency, rate, source (кэш курсов Нацбанка).
* import_batches: id, user_id, filename, format, status, счётчики строк.

Правило: одна запись entries порождает одну или несколько строк
ledger_entries. Любой баланс = сумма delta по target. Деньги целыми.

## 7. Открытые вопросы и нерешённое

* Pocketbase vs Supabase: РЕШЕНО в пользу self hosted Supabase (нужен
  Postgres, Pocketbase на SQLite отпал).
* Фронт React vs Svelte: РЕШЕНО, React + Vite + TypeScript (ADR-0005).
* Контракт единиц в API (minor vs основные): по умолчанию minor (целое),
  зафиксировать в реализации.
* Поведение частично валидного импорта: РЕШЕНО, полный откат, пока файл
  не исправлен целиком (ADR-0004).
* Пополнение от компании с комиссией за свой счёт: РЕШЕНО (ADR-0003).
  Комиссия списывается с остатка счёта зачисления, компенсация сначала
  гасит i_owe_company, остаток идёт в company_owes_me.

## 8. Стек и ограничения

* Только бесплатные и open source инструменты, self hosted на своём VPS
  под своим доменом (DNS, Caddy, Let's Encrypt).
* База Postgres (обязательно).
* Supabase self hosted (Docker): Postgres, PostgREST (авто API), GoTrue
  (Google OAuth), Storage.
* Движок расчёта: функции Postgres (plpgsql), вызов через RPC, в
  транзакции. Вся денежная логика на сервере, не на клиенте.
* Доп. логика (импорт, курсы Нацбанка, Claude Code ingestion): Supabase
  Edge Functions на Deno (TypeScript).
* Node как рантайм НЕ нужен. Node только как dev-сборка фронта (vite).
* Авторизация только через Google (Gmail). RLS по user_id на всех
  пользовательских таблицах.
* Деньги целыми в тиынах, без float.
