# 18: Импорт

**What to build:** Я загружаю CSV, Excel или JSON по той же схеме, что экспорт, вижу предпросмотр с ошибками по строкам и возможными дублями и подтверждаю. Одна ошибочная строка отменяет весь файл (ADR-0004). Повторная загрузка того же файла не создаёт дублей.

Спека: `.scratch/v1/spec.md` (формулы и числа тест-кейсов: `.scratch/v1/spec/03-engine-and-operations.md`, `06-testing.md`). Термины: `GLOSSARY.md`.

**Blocked by:** 17

**Status:** done

- [x] Предпросмотр: валидация каждой строки, сопоставление счетов и категорий по точному названию, возможные дубли по отпечатку в окне ±3 дня
- [x] Подтверждение одной транзакцией, при ошибке откат всей партии и пометка «неудачна», пересчёт один раз в конце, пропуск повторов по внешнему идентификатору
- [x] Экран импорта: шаблон и правила схемы, предпросмотр, подтверждение

## Comments

- Edge Function `import_parse` (`supabase/functions/import_parse`): multipart `file` → `{filename, format, rows, errors}`; CSV, xlsx, JSON и zip экспорта. Схема и правило знака из `_shared/schema.ts` (`importRow` рядом с `entryRecord`, тот же `amountSign`), поэтому импорт обратен экспорту. GET `?template=csv|xlsx|json` отдаёт шаблон, собранный кодом экспорта.
- Суммы без float: CSV текстом, JSON своим разборщиком с исходным текстом чисел, xlsx через `read-excel-file@9.3.12/universal` (MIT) с `parseNumber` = текст ячейки, округлённый строкой до 15 значащих цифр (как показывает Excel). Тест подменяет ячейку на `-1234.5599999999999` и получает `123456` тиынов. SheetJS не взят: отдаёт только float.
- Миграция `20261118120000_import.sql`: `import_batches` (RLS `apply_user_rls`, клиент только читает), FK `entries.import_batch_id`, RPC `import_preview` и `import_commit`. Проверка строки = те же `engine.entry_from_payload` → `check_entry` → `require_category` → `insert_entry`, что у `create_entry`; общий прогон `engine.import_run` для предпросмотра и подтверждения, по строке в подтранзакции, один `recompute` в конце. Ни одна общая функция движка не переопределена.
- Подтверждение при ошибке возвращает `ok: false` (не исключение): записи откатываются в подтранзакции, а `status = failed` и отчёт сохраняются в партии.
- Отклонения и решения: у личной траты в файле `source` обязателен (аванс из строк того же файла до пересчёта не виден); возможные дубли по умолчанию не создаются, владелец отмечает «Создать всё равно» (`p_exclude_lines`); идемпотентность и по id записи (экспорт пишет его в `external_id`). Подробно в README спеки.
- Тесты: pgTAP `170_import.test.sql` (32): TC-IMPORT-ATOMIC, TC-IDEMPOTENT-IMPORT, TC-DEDUP-IMPORT, ошибки проверки и пересчёта по строкам, round trip выгрузки в другого пользователя (те же записи, остатки, авансы и долг) и повторная загрузка без новых записей. Deno: разбор CSV/JSON/xlsx, `(1500.00)`, больше двух знаков, дрейф xlsx, дата Excel, round trip файлов экспорта во всех трёх форматах, zip, шаблон. vitest: `importPreview.ts`.
