# 16: Заметки и вложения

**What to build:** Я сохраняю заметку текстом и/или скрином, она ни на что не влияет и видна в инбоксе как новая. Из заметки делаю запись с предзаполненной формой, заметка становится разобранной со ссылкой на запись. К записи можно прикрепить файлы.

## Comments

2026-11-04, реализация:
- Миграция `supabase/migrations/20261116120000_notes_and_attachments.sql`: приватный бакет Storage `files` (20 МиБ, картинки JPG/PNG/WebP/HEIC/HEIF/GIF и PDF), политика `files_owner` на `storage.objects`: первый сегмент пути = свой user id и `is_allowed()`, на все действия. Таблицы `notes` (`note_status` new/processed, `linked_entry_id`, проверки «текст или скрин» и «processed ⇔ есть запись») и `attachments` (`entry_id` on delete cascade, `file_name`, `kind` receipt/screenshot/invoice) через `apply_user_rls`, с клиента только чтение. FK `entries.source_note_id` на `notes` (on delete set null).
- RPC: `create_note(text, attachment_path)`, `delete_note`, `convert_note_to_entry(note_id, payload)` (зовёт сам `create_entry`, любой тип, затем `source_note_id`, заметка processed + `linked_entry_id`, скрин заметки становится вложением записи `screenshot`; всё в одной транзакции), `add_attachment(entry_id, file_path, kind, file_name)`, `delete_attachment`. Путь файла проверяется: своя папка и объект есть в бакете (`file_not_found`). Новые коды: `note_empty`, `note_not_found`, `note_already_processed`, `file_not_found`, `attachment_not_found`.
- Удаление файлов: SQL не может удалить объект Storage (Storage API запрещает прямой DELETE), поэтому `delete_entry`, `delete_note`, `delete_attachment` возвращают `removed_files` (пути, на которые больше не ссылается ни заметка, ни вложение), клиент удаляет их через Storage API. Страховка: представление `v_orphan_files` (свои файлы без ссылок старше суток), экран заметок подчищает их при открытии.
- `create_entry` и `engine.update_entry` скопированы с тикета 15: присланный клиентом `source_note_id` отбрасывается, правка сохраняет прежний. `delete_entry` скопирован с тикета 13 (+ `removed_files`). `v_inbox`: ветка `kind = 'note'` и колонки `note_id`, `note_text`, `note_attachment_path` в конце; `v_inbox_count` без изменений.
- pgTAP `150_notes_attachments.test.sql` (56): заметка не меняет счётчики (и при полном пересчёте), инбокс и бейдж, разбор любого типа, атомарность, повторный разбор, ссылка на заметку, вложения и их удаление с записью, заметка снова новая после удаления записи, сироты, политики Storage (своя/чужая папка, неразрешённый, аноним), бакет, `not_allowed`. Проверено и на базе, поднятой как в CI (`supabase db start` без остальных сервисов): схема storage там есть.
- Экраны: раздел «Заметки» (боковая навигация и шапка): создание текстом и/или скрином (выбор файла на телефоне предлагает камеру), новые/разобранные, у разобранной ссылка на запись. «Сделать запись» (из заметок и из инбокса) открывает полную форму с заметкой сверху: название = первая строка, комментарий = вся заметка; сохранение зовёт `convert_note_to_entry`. В быстром вводе кнопка «Это заметка, не трата». В форме записи скрытый блок «Дополнительно: вложения»: у сохранённой записи файл прикрепляется сразу, у новой после сохранения. Чистые помощники `web/src/files.ts` (vitest).
- Отклонения: заметки создаются через RPC, а не прямым INSERT (док 05 разрешал), чтобы проверить путь скрина. Сумму из текста заметки форма не угадывает (только название и комментарий). Удалить можно и разобранную заметку через RPC, но на экране кнопка только у новой.
