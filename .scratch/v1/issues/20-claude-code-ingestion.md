## Comments

- 2026-11-04 (реализация): RPC `claude_ingest(p_token_hash, p_request)` (только service_role) находит владельца по SHA-256 хэшу токена, ставит его id в JWT-настройки транзакции и зовёт сами `create_entry` / `convert_note_to_entry` / `quick_capture`, поэтому проверка, движок, пересчёт и лист ожидания те же; id пользователя из запроса не берётся. Edge Function `claude_ingest` (`verify_jwt = false`) считает хэш, отсекает кривой токен без базы, ограничивает тело 64 КиБ, переводит коды в HTTP (401/403/429/413/400/422). Токен: `claude_token_generate` (один на владельца, показывается один раз, срок год), `claude_token_revoke`; таблица `claude_tokens` с `apply_user_rls` и GRANT клиенту только на подсказку и даты. Частота: 60 вызовов в минуту на токен (счётчик в строке токена; ошибки записи возвращаются JSON, а не исключением, чтобы счётчик и `last_used_at` не откатывались).
- Сверх тикета: action `context` (счета, категории, новые заметки с подписанной ссылкой на скрин на 10 минут: без него Claude Code не знает id) и `quick_capture` (ADR-0009 упоминает импорт Claude Code). Экран: новый вторичный раздел «Настройки» с блоком «Доступ для Claude Code» (выпустить, сменить с подтверждением, отозвать, последний вызов, срок).
- Тесты: pgTAP `200_claude_ingest.test.sql` (41: хэш вместо токена, неверный/истёкший/отозванный токен, смена, только service_role, запись под владельцем со счётчиками, ошибки проверки теми же кодами, разбор заметки, чужие данные недоступны, лист ожидания, частота); Deno `claude_ingest/handler_test.ts` (13, база подменена); vitest `formatDateTime`. Проверено вживую curl'ом через шлюз 127.0.0.1:54321 и скриншотами экрана.
- Для тикета 21 (деплой): в self-hosted edge runtime проверка JWT глобальная (`VERIFY_JWT`), для `claude_ingest` её нужно выключить; иначе Claude Code шлёт anon-ключ в `Authorization`, токен в `X-Claude-Token` (функция понимает оба).
