## Comments

- Edge Function `export` (`supabase/functions/export`): `{from?, to?, format}` → один zip с `expenses.<fmt>` и `company_settlement.<fmt>` (решено: архив, а не две загрузки, одинаково для всех форматов). Читает с JWT пользователя выборки `v_export_entries` и `v_settlement_movements` (миграция `20261117120000_export.sql`), деньги текстом (`::text`), страницами по 1000.
- Схема колонок и правило знака определены один раз в `supabase/functions/_shared/schema.ts` (тикет 18 импортирует её же) и описаны в доке 04, раздел 8. К 15 полям импорта добавлены `settlement_direction, adjustment_target, adjustment_mode, adjustment_affects_advance, parent_external_id, rate, rate_source, amount_kzt, in_analytics`. Знак `amount` = движение денег по счёту `account`; корректировка несёт свой знак в знаке суммы; комиссия всегда минус; взаимозачёт плюс.
- Черновики не выгружаются. `external_id` в файле: свой или id записи (повторный импорт выгрузки не создаст дублей); возврат ссылается на трату через `parent_external_id`.
- `company_settlement`: строка на запись, изменения обеих сторон, обе стороны и итог после; стороны «после» накоплены по всей истории (фильтр периода их не обрезает), pgTAP проверяет это на сценарии разбора долга из 090.
- xlsx: `write-excel-file@4.1.1` (MIT, зависит только от `fflate`), zip: `fflate@0.8.2`. SheetJS отвергнут: подменяет формат встроенным id 40 и пишет мусорный numFmt. Тест вскрывает `sheet1.xml`/`styles.xml`: ячейка числовая, её стиль ведёт на `formatCode="#,##0.00;[Red](#,##0.00)"`. Проверено и в живом edge runtime стека (все три формата).
- JSON: суммы числами с двумя знаками (`-1500.00`, пишутся из десятичной строки); CSV: UTF-8 с BOM для Excel, RFC 4180, CRLF.
- Экран «Экспорт»: период (этот месяц, прошлый, этот год, всё время, свой) и формат, кнопка «Скачать архив»; скачивание через `fetch` (functions.invoke читает zip как текст).
