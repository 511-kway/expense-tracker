# Трекер затрат: документация для разработки

Версия 1 (MVP). Дата: 2026-11-03.

Это комплект спецификаций для реализации силами ИИ агентов (spec driven development). Личное приложение для учёта затрат семьи и расчётов с компанией. Веб кабинет первым, мобилка позже.

## Как пользоваться этим комплектом

Это источник правды. Пиши код строго по этим докам. Если по ходу находишь пробел или противоречие, не додумывай молча: предложи правку спеки, зафиксируй решение, потом кодь.

## Порядок чтения

1. `00-overview.md` — что это, цели, рамки, глоссарий. Прочитать первым.
2. `01-architecture.md` — стек, почему не Node, авторизация, хостинг, безопасность.
3. `02-data-model.md` — таблицы, поля, enum, индексы, связи. Основа.
4. `03-engine-and-operations.md` — движок расчёта, эффект каждой операции, реплей, edge cases. Самый важный.
5. `04-functional-spec.md` — функционал по областям, поведение без визуала.
6. `05-api.md` — RPC-функции, представления, Edge Functions, коды ошибок.
7. `06-testing.md` — стратегия и конкретные тест-кейсы с числами.

Визуал (экраны, вёрстка) в этот круг не входит, прорабатывается отдельно. Прототипы существуют как референс.

## Главные принципы (не нарушать)

1. **Баланс не хранится числом.** Остаток, аванс и долг выводятся из журнала `ledger_entries`. Любое изменение пересобирает ledger через `recompute`.
2. **Вся денежная логика на сервере.** Движок это функции Postgres в транзакции. Клиент только собирает ввод, зовёт RPC, показывает результат. Никаких денежных вычислений и прямых записей в `entries`/`ledger_entries` с клиента.
3. **Деньги целыми** в минимальных единицах (тиыны). Без float.
4. **Аванс считается по реальной дате** операции, с хронологическим реплеем. Запись задним числом корректна за счёт recompute.
5. **Нет Node как рантайма.** Supabase self hosted плюс функции Postgres плюс Edge Functions на Deno. Node только dev-сборка фронта.

## Порядок реализации (вехи)

Делать итерациями, каждая с тестами, которые зелёные перед следующей.

1. **Схема и движок.** Миграции: таблицы, enum, индексы, RLS (док 02). Функции Postgres: `create_entry`, `update_entry`, `delete_entry`, `recompute`, валидация (доки 03, 05). Представления (`v_account_balances`, `v_company_settlement`, `v_settlement_breakdown`, `v_overview`). Юнит-тесты движка (док 06, разделы 3 по 10) зелёные.
2. **Авторизация и справочники.** Google OAuth через GoTrue. CRUD счетов (с guard архива) и категорий. Сиды справочников владельца.
3. **Ввод операций.** RPC и формы: полная запись, быстрый capture (draft), инбокс, promote_draft. Живой предпросмотр эффекта (считает по правилам движка).
4. **Заметки и вложения.** Storage, заметки, convert_note_to_entry.
5. **Импорт и экспорт.** Edge Function парсинга, import_preview/commit (атомарно, дедуп, идемпотентность), экспорт по единой схеме. Тесты раздела 11.
6. **Валюта.** Edge Function курсов Нацбанка, таблица `fx_rates`, три способа пересчёта. Тесты раздела 10.
7. **Claude Code ingestion.** Защищённый вход создания записей.
8. **Обзор и баланс с компанией.** Агрегаты и раскрытие долга.

Мобилка (Flutter, виджет быстрого capture) и встроенная аналитика это отдельный круг после MVP.

## Определение готового (definition of done) для каждой задачи

- Код соответствует спеке.
- Тесты по доку 06 для затронутой области написаны и зелёные.
- Инварианты (док 03, раздел 10) проверяются в тестах.
- Миграции применяются на чистую базу одной командой.
- RLS на месте для новых таблиц.
- Нет денежной логики на клиенте.

## Тесты и ревью (сейчас и дальше)

- Тесты пишутся вместе с кодом по доку 06. Движок покрывается в первую очередь.
- CI прогоняет миграции и тесты на чистой базе. Зелёные тесты условие мёржа.
- Позже добавляется ai code reviewer в CI (проверка спека-соответствия, безопасности RLS, отсутствия логики на клиенте). Его правила выведутся из этих доков.
