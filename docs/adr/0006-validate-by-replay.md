# 6. Ограничения «до нуля» проверяются реплеем по всей хронологии

Статус: принято (2026-11-03).

## Контекст
В спеке 03 проверки `debt_overpay`, `advance_return_too_big`, `refund_too_big` выполнялись по текущему состоянию в момент создания. Правка или удаление задним числом (например, удаление траты, долг по которой уже погашен) могли увести счётчик в минус в прошлом, и никто бы это не поймал.

## Решение
- Любая денежная RPC (create/update/delete/promote/import_commit) делает изменение, затем `recompute` в той же транзакции.
- Реплей проверяет ограничения в момент каждой операции по хронологии: долг не уходит ниже нуля (settlement, repay_debt), возврат аванса не больше аванса на дату, refund не больше остатка исходной.
- Нарушение даёт исключение с кодом ошибки (док 05) и id операции, на которой сломалось. Транзакция откатывается целиком.
- Предварительная проверка по текущему состоянию остаётся только для быстрой ошибки в форме, источник правды это реплей.
